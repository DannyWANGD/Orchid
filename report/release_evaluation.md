# Orchid 92M 模型复测与展示建议

2026-11-21 · 最终交付的韵律续训权重 · 91,843,584 个参数。复测包括 600 条 GPU 生成、六组同题原诗细读、六个边界输入及 CPU/GPU 推理计时。[机器可读结果](evidence/release-evaluation-20261121.json)

## 建议优先做什么

1. **补一次最终版的真人盲评。** 从一词、两词、三词题各抽 10 道，同题比较自由和默认模式，各由两位读者按 v2 独立评阅。切题看语义，接受同义转述和合理暗示。可读性看句意能否读懂。连贯性只评可解析的四句。可读性和连贯性均至少 3 分才评意境。汇总保留每位评阅者的适用数、配对数和各项分布。用新的独立题验证后续优化。[v2 量表](blind_review/reviewer_guide_v2.md)
2. **做单页 HTML 展示。** 首屏给 1～3 个关键词输入、生成按钮和可选种子。并排显示同题的自由与默认生成，列出四句原文、第二和第四句韵脚、平水韵部、原词覆盖以及耗时。给出自然与生硬的样例，方便读者判断诗意。可先做纯静态版，点击预设题回放随源码分发的封存输出。现场演示再接本机 Python 接口，让进程启动时加载一次模型。输入提示说明每词 1～2 字及字表范围，并显示可纠正的输入错误。
3. **优先改善两词和三词题的成诗质量。** 当前带关键词的候选按模型对数概率和重复惩罚选取。可以先对照现行排序与加入句意连贯性、关键词邻接自然度的排序，在验证题调节后用新题盲测。监督数据可补充同一情境下自然共现的多意象题，并平衡题词数。需要展示严格五言近体时，再单列完整平仄模式及其对可读性的影响。[当前解码实现](../orchid/prosody_decode.py)

## 固定测试

50 道新题各用种子 11、22、33，共 150 次请求。四个模式用同一权重与 FP32，温度 0.8、top-k 50、top-p 1、生成预算 64。600 条复测记录除计时字段外逐项一致，结果可与原实验逐条对照。[封存逐条结果](evidence/prosody-study/test/generations.jsonl) · [封存指标](evidence/prosody-study/test/metrics.json)

| 模式 | 四句五字 | 第 2、4 句异字同平声韵 | 原词全覆盖 | 三项均达标 | CUDA p50 / p95 |
|---|---:|---:|---:|---:|---:|
| 自由 | 148/150 | 92/150 | 25/150 | 17/150 | 0.033 / 0.034 秒 |
| 限字数 | 150/150 | 93/150 | 25/150 | 17/150 | 0.053 / 0.054 秒 |
| 限字数与押韵 | 150/150 | 150/150 | 25/150 | 25/150 | 0.052 / 0.053 秒 |
| 默认，另要求用词并选优 | 150/150 | 150/150 | 150/150 | 150/150 | 0.195 / 0.203 秒 |

原词覆盖要求每个输入词都连续出现在同一句。自由模式的一词题覆盖 25/48，两词和三词题各为 0/51。默认模式在三类题分别达到 48/48、51/51、51/51。默认输出的 150 首完整文本互异，使用了 24 个可确认的平声韵部。按已登记口径检索训练集，整首、长诗片段及近重复均为 0/150，也未出现一首内重复整句。六个边界输入均按预期返回错误，覆盖空词表、重复、过长、超出词数和字表外字形。[测试题与边界定义](../artifacts/eval_prompts.json)

按四套逐字常格同时核验平仄与该格押韵，默认输出有 1 首合、146 首不合、3 首待判。逐字常格检查采用固定韵表，字位变通和多音字语境可参考归档的八首个案复核。[常格诊断](evidence/meter-prosody.json) · [八首 AI 复核](prosody_source_audit.md#8-首样例的-ai-格律复核)

## 同题细读

每个词数取冻结题的首题与末题，统一种子 11。六对为本次看得到生成方式的定性阅读。已归档的真人 v1 和同批 AI v2 评分来自早期 14M 输出，最新 92M 的四项主观指标仍需单独评阅。[原评阅范围](blind_review/README.md)

| 题目 | 自由生成 | 默认生成 |
|---|---|---|
| M001 霜 | 前两句写霜蟹，后两句的数量与物象脱节 | 后句收「英」，与「烹」同韵，意象的跳跃仍在 |
| M016 清霜 | 「秋霜」「霜重」回应清寒，首句抽象且承接较弱 | 山谷、井梧和岁末衰老形成一条可读的线索 |
| M017 霜、孤舟 | 长江、烟波呼应水路，但落到「孤山」，霜意较弱 | 霜叶、孤舟、寒夜同置一景，「孤舟寒夜水」句法偏紧 |
| M033 清風、桂花 | 露与风有时令感，桂花意象缺失 | 桂香与风构成开篇，末句的「移取」指向含混 |
| M034 孤舟、春雨、煙波 | 写到春潮与独立远眺，春潮有季候联系 | 三词都落在水景里，「春雨夜來雨」用词重复 |
| M050 南山、小雨、月影 | 夜雨、竹钟和闲情相连，山与月缺少铺垫 | 三词可定位，「小雨暗不出」较难理解，末句转得急 |

例如「霜、孤舟」默认生成「霜葉滿空落，悲心無處尋。孤舟寒夜水，獨自照秋林。」四句五字，韵脚「尋／林」同部，霜叶和孤舟都参与了夜行图景。同批「孤舟、春雨、煙波」默认生成「煙波春渺渺，寂寂孤舟閑。春雨夜來雨，空江寒葦山。」字面达标，可读性仍受词语堆叠影响。两类样例均适合展示。

## 推理速度与资源

使用同一导出的 FP32 模型，单请求串行，每种模式每设备预热 2 次、计时 30 次。CPU 是 i9-14900K、2 个 PyTorch 线程，GPU 是 RTX 4080 SUPER，PyTorch 为 2.14.1+cu126。p95 取排序后第 `ceil(0.95 × n)` 个值。计时从权重驻留后的生成开始，包含候选采样和选优。模型读盘、文件哈希校验及转移到设备另计，实测每次约 0.8～1.2 秒。

| 设备 | 自由 p50 / p95 | 默认 p50 / p95 | 默认 PyTorch 峰值分配 |
|---|---:|---:|---:|
| RTX 4080 SUPER | 0.050 / 0.090 秒 | 0.198 / 0.208 秒 | 约 370 MiB |
| i9-14900K | 0.622 / 0.757 秒 | 2.532 / 2.626 秒 | — |

默认模式采样四个候选。面向互动展示，GPU 响应充足，CPU 可用同一常驻进程处理输入并显示生成状态。若需压低 CPU 延迟，可以将 CLI 的 `--candidates 1` 和默认 4 做同题测试，再决定展示采用哪一档。显存数字采用 PyTorch 的已分配峰值，统计范围包含模型张量和生成期临时张量。

## 复跑命令

在模型包根目录用 `--checkpoint model`。使用本地导出目录时可传 `--checkpoint dist/orchid-92m-prosody`。完整评估需要先构建唐宋数据与监督集，以便核验验证集的指纹和检查训练集重合。[数据准备](../README.md#单卡扩容92m-唐宋版)

```bash
python -E scripts/evaluate_prosody.py test --checkpoint model \
    --selection report/evidence/prosody-study/validation/metrics.json \
    --device cuda --output runs/prosody-replay
python -E scripts/evaluate_meter.py --generations runs/prosody-replay/generations.jsonl \
    --suite test --group-by mode --output runs/prosody-replay/meter.json

for mode in raw rhymed; do
    python -E scripts/benchmark_generation.py --checkpoint model --mode "$mode" \
        --devices cuda cpu --requests 30 --output "runs/benchmark-$mode.json"
done
```

只测速度可直接在模型包中跑最后一组命令。CPU 环境使用 `--devices cpu`。更换设备后同一采样种子的原诗可能变化，比较逐字复现时以同一 CUDA 环境为准。
